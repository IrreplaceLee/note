# 张量变形：reshape 与转置的区别

> 整理日期：2026-08-01 16:14
> 关联书籍：《PyTorch 深度学习实战》

## 本轮学到的核心知识

### 一、reshape：重新排布形状，数据顺序不变

- **作用**：把张量换个形状来装，但里面的数字**个数、顺序都不变**——像把一队数字重新折行。
- **铁律：变形前后元素总数必须相等**。`(2, 3)` 一共 6 个数，只能变成同样装得下 6 个的形状：`(3, 2)`、`(6,)`、`(1, 6)`、`(6, 1)`；想变成 `(2, 2)`（只装 4 个）会直接报错。
- **偷懒技巧 `-1`：这一维让 PyTorch 自己算**
  - `t.reshape(3, -1)` → 我要 3 行，列数你算（6÷3=2）→ `(3, 2)`
  - `t.reshape(-1, 2)` → 我要 2 列，行数你算 → `(3, 2)`
  - `t.reshape(-1)` → 拉成一条一维直线 → `(6,)`
  - ⚠️ 最多只能写**一个** `-1`（写两个 PyTorch 也没法算）。

### 二、转置（transpose）：行列对调

- **作用**：把行和列对调，相当于沿「左上→右下」对角线把矩阵翻过去。
- **规则**：原来在第 i 行第 j 列的数，转置后跑到第 j 行第 i 列。
- **几种写法**：

| 写法 | 说明 | 适用 |
|------|------|------|
| `t.T` | 最简洁 | 二维矩阵 |
| `t.t()` | 和上面等价 | 只能二维 |
| `torch.transpose(t, 0, 1)` | 交换第 0 维和第 1 维 | 任意维度 |
| `t.permute(1, 0)` | 重新排列所有维度顺序 | 任意维度、更灵活 |

初学阶段二维矩阵记住 **`t.T`** 就够；等以后处理 3 维、4 维数据，再用 `transpose` / `permute` 交换指定维度。

### 三、⭐ 核心：reshape 和转置的区别（最容易混）

两者都能把 `(2, 3)` 变成 `(3, 2)`，但结果**完全不同**。用同一个 `t = [[1,2,3],[4,5,6]]`：

```
原始 t:               reshape(3, 2):        转置 .T:
[[1, 2, 3],           [[1, 2],              [[1, 4],
 [4, 5, 6]]            [3, 4],               [2, 5],
                       [5, 6]]               [3, 6]]
```

- **reshape**：数字顺序 `1 2 3 4 5 6` 完全不变，只是重新折行。
- **转置**：行列互换，数字顺序被打乱成 `1 4 2 5 3 6`。

一句话记：**reshape 只换形状不换顺序；转置是真的把矩阵「翻」了一下。**

## 我踩过的坑 / 薄弱项

- **误区**：以为 reshape 和转置能互相替代（反正都能把 `(2,3)` 变 `(3,2)`）。**正解**：结果不同——reshape 不动数据顺序，转置会把行列互换、顺序打乱。
- **易混：两个 `-1`**（名字一样，含义完全不同）：
  - `shape[-1]` 的 `-1` = 取「倒数第一维」（**取值**），见 [张量形状与索引](张量形状与索引-shape负数索引-1614.md)。
  - `reshape(3, -1)` 的 `-1` = 「这维你帮我算」（**占位符**）。
- **小坑：转置后紧接着变形可能报错**——转置是「零拷贝、只换看法」，内存里数据没真搬动（叫 not contiguous）。此时 `.view()` 会报错；解决办法是先 `.contiguous()` 把数据整理连续，或直接用更省心的 `.reshape()`（它必要时会自动复制）。底层机制详见 [张量底层存储（storage/stride/view）](../20260729/张量底层存储-storage与stride与view-0020.md)。

## 可运行的代码示例

```python
import torch

t = torch.tensor([[1, 2, 3],
                  [4, 5, 6]])        # 形状 (2, 3)

# ---------- reshape：顺序不变，只换形状 ----------
print('reshape(3,2):\n', t.reshape(3, 2))    # [[1,2],[3,4],[5,6]]
print('reshape(-1):',    t.reshape(-1))      # tensor([1,2,3,4,5,6]) 拉成一维
print('reshape(3,-1):\n', t.reshape(3, -1))  # -1 让 PyTorch 自动算列数 → (3,2)

# ---------- 转置：行列对调 ----------
print('t.T:\n',          t.T)                     # [[1,4],[2,5],[3,6]]
print('transpose:\n',    torch.transpose(t, 0, 1))# 同上，通用写法
print('permute:\n',      t.permute(1, 0))         # 同上，permute 版

# ---------- 对比：同样 (2,3)->(3,2)，结果不同 ----------
print('reshape 结果:\n', t.reshape(3, 2))    # 顺序不变
print('转置   结果:\n', t.T)                 # 行列互换

# ---------- 转置后变形：先 contiguous 更稳妥 ----------
tt = t.T                                  # 转置后 not contiguous
# print(tt.view(-1))                      # ← 若用 view 会报错 not contiguous
print('拉平:', tt.contiguous().reshape(-1))  # 先连续化再拉平，稳妥
```

## 延伸提示

- 想搞懂「为什么转置是零拷贝、为什么会 not contiguous」，看 [张量底层存储（storage/stride/view）](../20260729/张量底层存储-storage与stride与view-0020.md)——那篇从内存 stride 层面把 contiguous 讲透了。
- `reshape` 和 `view` 很像：`view` 要求内存连续、更省（零拷贝），`reshape` 更省心（必要时自动复制）。初学先统一用 `reshape` 不容易出错。
- 除了 reshape/转置，增减维度还有专门操作（`unsqueeze`/`squeeze`/`stack`/`cat`），见 [批次维度与多图处理（unsqueeze/stack/cat）](../20260726/批次维度与多图处理-unsqueeze-stack-cat-1535.md)。
- **与研究任务的联系**：做多模态融合、把影像送进网络时，经常要用 `reshape` / `permute` 调整维度顺序，去对齐不同模态或匹配网络输入（例如把 `(通道, 高, 宽)` 拉平成一维送进全连接层）。分清「reshape 不换数据顺序、转置/permute 会换」，能避免把数据悄悄搞乱却不报错的隐蔽 bug。
