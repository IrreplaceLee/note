# RGB 通道与图像的张量表示

> 整理日期：2026-07-25 00:40
> 关联书籍：《PyTorch 深度学习实战》（第 2、3 章）

## 本轮学到的核心知识

- **数字图像本质是「一堆数字」**。屏幕上每个小点叫**像素（pixel）**，一张图就是像素排成的网格。电脑里没有「颜色」，颜色也要用数字表示。

- **RGB = Red 红 / Green 绿 / Blue 蓝**，三种「光的原色」。自然界几乎所有颜色都能由这三种按不同比例混合出来：
  - 红 + 绿 = 黄；红 + 绿 + 蓝（都满）= 白；全为 0 = 黑。
  - 每个像素用**三个数字**描述红、绿、蓝各有多强，通常取值 **0~255**（0 最弱，255 最强）。

  | 颜色 | R | G | B |
  |------|-----|-----|-----|
  | 纯红 | 255 | 0 | 0 |
  | 纯绿 | 0 | 255 | 0 |
  | 纯蓝 | 0 | 0 | 255 |
  | 白色 | 255 | 255 | 255 |
  | 黑色 | 0 | 0 | 0 |

- **「通道（channel）」= 把某一种颜色单独拎出来的那一层**。红通道 = 全图所有像素的红色分量组成的一张「表」；绿、蓝通道同理。**一张彩色图 = 红、绿、蓝三张表叠在一起。**

- **一张 RGB 图存成张量，有 3 个维度：`[通道, 高度, 宽度]`**：
  - 通道维 = 3（红、绿、蓝三层）
  - 高度维 = 有多少行像素
  - 宽度维 = 有多少列像素
  - 例：一张 256×256 彩色图，张量形状是 `[3, 256, 256]`。
  - 定位「第 100 行第 50 列的红色分量」需要三个坐标：`张量[0, 100, 50]`（0 代表红通道）。这就是为什么需要三维。

- **通道数不固定为 3**，取决于数据本身：
  - 彩色照片：3 通道（RGB）
  - 灰度图（黑白）：**1 通道**，形状 `[1, 高, 宽]`

## 我踩过的坑 / 薄弱项

- **薄弱项**：不清楚「通道」是什么。正解——通道就是「某一种颜色单独的那一层亮度表」，彩色图是 3 层叠起来。
- **易混点**：真实图片像素值通常是 0~255 的整数，但送进神经网络前一般会**归一化到 0~1**（除以 255）或做标准化。所以用 `torch.rand`（0~1）模拟图片很贴近实际。

## 可运行的代码示例

```python
# ===== Kaggle Notebook 可直接运行 =====
import torch

# 造一个假的 RGB 小图：3 通道，高 4，宽 5
img = torch.rand(3, 4, 5)      # 0~1 随机数，模拟一张图

print("整张图形状：", img.shape)   # torch.Size([3, 4, 5]) → [通道, 高, 宽]

# 分别取出三个通道（每个是一张 4×5 的“表”）
红通道 = img[0]   # 第 0 层
绿通道 = img[1]   # 第 1 层
蓝通道 = img[2]   # 第 2 层
print("单个通道形状：", 红通道.shape)   # torch.Size([4, 5])

# 取某个像素（第 2 行第 3 列）的红色分量
print("该像素的红色值：", img[0, 2, 3])
```
