# 预训练模型大小与加载方式

> 整理日期：2026-07-26 15:35
> 关联书籍：《PyTorch 深度学习实战》第 2 章

## 本轮学到的核心知识

### 模型有多大？怎么估算
- 文件大小主要 = **参数量 × 每个参数占的字节数**：
  - **FP32**（单精度）：每个参数 4 字节 → `文件大小 ≈ 参数量 × 4`
  - **FP16**（半精度）：2 字节
  - **INT8**（量化）：1 字节
- 例：ResNet-101 有 4400 万参数 → 44M × 4 ≈ **170 MB**（相当于一部高清电影）。

### 常见模型大小（FP32）
| 类型 | 模型 | 参数量 | 大小 |
|---|---|---|---|
| 视觉 | ResNet-18 / 50 / 101 | 11 / 25 / 44 M | 45 / 98 / **170** MB |
| 视觉·手机 | MobileNet v2 | 3.5 M | ~14 MB |
| 语言 | BERT-base | 110 M | ~440 MB |
| 语言·大 | LLaMA-7B / 70B | 7 / 70 B | ~14 / 140 GB |
| 语言·超大 | GPT-3 | 175 B | ~350 GB |

- **视觉模型**：几十 MB ~ 几百 MB。
- **语言模型（LLM）**：从 GB 起步到 TB 级，比视觉模型大 100~1000 倍。（B = Billion 十亿，「7B」= 70 亿参数）

### 量化能「瘦身」
同一个模型换存储方式大小差很多：FP32(100%) → FP16(50%) → INT8(25%) → INT4(12.5%)，精度损失依次略增。开源大模型的「Q4/Q8」版本就是量化压缩过的，笔记本也能跑（如 LLaMA-7B 量化到 4-bit 只 ~4 GB）。

### 加载方式（2026 年现状）——书里的 Torch Hub 已过时
- 书（2020 出版）说用 **Torch Hub + `hubconf.py`** 是标准做法，**现在能用但已边缘化**（依赖 GitHub 仓库结构、版本管理弱、权重散落、代理下常连不上）。
- 现在的标准打法：

| 方式 | 适用场景 | 代表 |
|---|---|---|
| `torchvision.models` | 经典视觉模型 | ResNet, VGG, EfficientNet |
| **Hugging Face `transformers`** ⭐ | 绝大多数现代模型 | BERT, GPT, LLaMA, ViT, CLIP |
| **timm** | 视觉模型大全（600+） | 社区首选 |
| `torch.hub` | 兼容老项目 | YOLOv5, DINO |

## 我踩过的坑 / 薄弱项

- 以为书里的 Torch Hub 是当下主流。实际上 2020 年后社区几乎全转向 **Hugging Face**；学书时用书里方法没问题（原理是永恒的），实战换成 HF / timm 更省心。
- 不清楚 `pretrained=True` 下载的东西存哪：缓存在本地 `~/.cache/torch/hub/checkpoints/`，第一次下（ResNet-101 约 170 MB，10~30 秒），之后读缓存秒开。

## 可运行的代码示例

```python
# 方式一：torchvision（经典视觉模型，书里用的）
from torchvision import models
resnet = models.resnet101(pretrained=True)     # 下载 ~170MB，缓存到本地

# 方式二：timm（视觉模型大全，实战首选）
import timm
model = timm.create_model('resnet50', pretrained=True)

# 方式三：Hugging Face（现代模型/NLP/多模态标准）
from transformers import AutoModel, AutoTokenizer
model = AutoModel.from_pretrained("bert-base-uncased")
tokenizer = AutoTokenizer.from_pretrained("bert-base-uncased")
```
