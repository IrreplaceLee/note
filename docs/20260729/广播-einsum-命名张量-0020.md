# 广播、加权求和、einsum 与命名张量（RGB转灰度案例）

> 整理日期：2026-07-29 00:20
> 关联书籍：《PyTorch 深度学习实战》（第 3 章 命名张量）

## 背景：一个贯穿的例子——把 RGB 彩图转成灰度

- 一张图 `img_t` 形状 `[通道=3, 高=5, 宽=5]`；一批图 `batch_t` 形状 `[批=2, 通道=3, 高=5, 宽=5]`。
- 转灰度 = 把 3 个颜色通道合成 1 个亮度值。RGB 标准权重 `[0.2126, 0.7152, 0.0722]`（绿色权重最大，因为人眼对绿最敏感）。
- 本篇用这个例子串起 4 个知识点：**负数维度、广播、einsum、命名张量**。

## 本轮学到的核心知识

### 1. 负数维度让一份代码通用
- `mean(-3)` / `sum(-3)` 里的 `-3` 表示「倒数第 3 维」，从右往左数。
- 为什么用负数而不写死 0 或 1：三维单图通道在第 0 维、四维批次通道在第 1 维，**位置不同**；但从右数都是**倒数第 3 维**。用 `-3` 就能同时兼容单图和批次，一份代码通用。
- `img_t.mean(-3)`：沿通道维求平均 → `(3,5,5)` 变 `(5,5)`；`(2,3,5,5)` 变 `(2,5,5)`。求平均/求和后，那一维消失。

### 2. 广播（broadcasting）：形状不同也能逐元素运算
- 规则：**从右往左对齐维度**，某一维要么相等、要么其中一个是 1（长度 1 的维度会被自动「复制拉伸」去匹配）。
- 权重 `weights` 是 `(3,)`，要和 `(3,5,5)` 相乘，得先把它补成 `(3,1,1)`：
  - `unsqueeze(-1)` 在末尾加一维：`(3,) → (3,1)`；再 `unsqueeze_(-1)`（带下划线，原地）：`(3,1) → (3,1,1)`。
- 补好后 `(3,1,1) * (3,5,5)`：后两维的 1 自动拉伸到 5，实现「每个通道乘各自权重」。再 `sum(-3)` 沿通道加起来就是加权灰度。

### 3. einsum：一行字符串描述维度运算
- `torch.einsum('...chw,c->...hw', img_t, weights)` 一句顶前面一整段。
- 字符串读法：逗号分隔各输入的维度记号；`c=通道 h=高 w=宽`；`...` 表示「前面可能还有任意多维」（兼容 batch）；`->` 右边是输出。
- **在输入出现、但输出没有的字母（这里 c）→ 沿该维相乘后求和**，正是加权求和。
- 优点简洁，缺点可读性差——所以书里接着引入命名张量。

### 4. 命名张量（named tensors）：给维度起名字
- 痛点：靠「第几维」记维度容易错。命名张量给每一维起名字，代码更可读、还能自动查错。
- 创建时命名：`torch.tensor([...], names=['channels'])`。
- 给已有张量补名：`refine_names(..., 'channels','rows','columns')`，`...` 表示「左边剩余维度先不命名」，名字**从右往左对齐**。
- 按名字对齐：`weights_named.align_as(img_named)` 自动把权重补成 `(3,1,1)`，**不用手动数维度 unsqueeze**。
- 按名字运算：`(img * w).sum('channels')`——直接写维度名，一眼看懂「沿通道求和」。
- **最大好处：名字对不上会直接报错**，而不是靠广播悄悄算出错误结果。普通张量这种错常常不报错但结果全错，极难查。
- ⚠️ 命名张量是**实验特性**，很多函数还不支持，运行会有 UserWarning。实际用法：内部用名字算，对外用 `rename(None)` 去掉名字变回普通张量。

## 我踩过的坑 / 薄弱项

- **薄弱项**：不理解为什么求和要写 `-3` 这种负数。**正解**：为了同时兼容「单图」和「一批图」两种形状——通道维从右数位置固定。
- **薄弱项**：不懂 `unsqueeze` 补一堆长度 1 的维度有什么用。**正解**：为了让广播能对齐；长度 1 的维度会自动拉伸匹配。
- **易错**：`unsqueeze`（返回新张量）和 `unsqueeze_`（下划线，原地改）容易混——沿用「下划线=原地」的约定。

## 可运行的代码示例

```python
# ===== Kaggle Notebook 可直接运行 =====
import torch
img_t = torch.randn(3, 5, 5)       # [通道, 高, 宽]
batch_t = torch.randn(2, 3, 5, 5)  # [批, 通道, 高, 宽]
weights = torch.tensor([0.2126, 0.7152, 0.0722])

# 1) 负数维度：一份代码兼容单图和批次
print(img_t.mean(-3).shape)        # (5, 5)
print(batch_t.mean(-3).shape)      # (2, 5, 5)

# 2) 广播加权求和：先把权重补成 (3,1,1)
uw = weights.unsqueeze(-1).unsqueeze(-1)   # (3,) → (3,1,1)
img_gray = (img_t * uw).sum(-3)
print(img_gray.shape)              # (5, 5)

# 3) einsum 一行搞定（自动兼容 batch）
g = torch.einsum('...chw,c->...hw', batch_t, weights)
print(g.shape)                     # (2, 5, 5)

# 4) 命名张量：可读 + 自动查错（会有实验特性警告，正常）
img_named = img_t.refine_names(..., 'channels', 'rows', 'columns')
w_named = torch.tensor([0.2126, 0.7152, 0.0722], names=['channels'])
w_aligned = w_named.align_as(img_named)         # 自动对齐成 (3,1,1)
gray = (img_named * w_aligned).sum('channels')  # 按名字求和
print(gray.shape, gray.names)                   # (5,5) ('rows','columns')
print(gray.rename(None).names)                  # 去名字变回普通张量
```

## 延伸提示

- **前置**：RGB 图像怎么用张量表示见 [RGB通道与图像的张量表示](../20260725/RGB通道与图像的张量表示-0040.md)；批次维度与 `unsqueeze/stack/cat` 见 [批次维度与多图处理](../20260726/批次维度与多图处理-unsqueeze-stack-cat-1535.md)。
- **广播**是 PyTorch 里最高频的隐形机制，几乎每个逐元素运算都在用，务必吃透「从右对齐、1 可拉伸」这条规则。
- **和研究方向的联系**：`einsum` 和广播是 **Transformer / GCN** 里做注意力、邻接矩阵传播的核心算子，将来读那些模型代码会大量遇到。**多模态融合**时不同模态张量形状各异，靠广播 + 维度对齐才能相加/相乘——命名张量的「按名字对齐」思想正是为解决这种维度混乱而生。
